# Приоритизация заявок

Правила v1 — воспроизводимая эвристика, а не предсказание сделки. Оценка помогает выбрать порядок просмотра; решение принимает администратор. Внешние AI-сервисы не используются.

## Отдельные показатели

- Срочность: высокий, средний, низкий или неопределённый срок.
- Соответствие: найдены признаки направления либо требуется уточнение.
- Готовность: достаточно ли конкретики для разговора.
- Общий приоритет: сумма баллов с объяснением каждого признака.

## Баллы

| Признак | Баллы |
| --- | --- |
| Срок «срочно», «сегодня», «завтра», «в течение недели», «до недели», «до 7 дней» | 50 |
| Срок с «месяц», «в течение 30 дней», «2/две недели», «3/три недели», «4 недели» | 25 |
| «Не срочно», «без спешки», «квартал», «позже», 2–9 месяцев | 5 |
| Нет срока либо свободный текст не распознан | 0 |
| В задаче есть CRM, заявки, интеграция, бот, Telegram, автоматизация, синхронизация, уведомления или обмен данными | 20 |
| Описана проблема: вручную, потери, дубли, ошибки, задержки, долго, не успевают | 10 |
| Указано действие: создавать, собирать, передавать, связать, настроить, снизить, сократить, уведомлять, распределять, проверять | 10 |
| Указанный бюджет попадает в диапазон услуги на момент создания | 5 |
| Роль содержит собственник, директор, руководитель, основатель, owner или CEO | 5 |

Поиск выполняется без учёта регистра по основам слов. Это простое сопоставление: отрицания и сложный контекст в описании задачи не интерпретируются. Для сроков признаки «не срочно», «без спешки» и долгосрочного плана проверяются раньше близких сроков. Нераспознанные даты не угадываются и требуют уточнения. Специальные формулировки, например «не горит», без распознанного срока остаются неопределёнными.

Общий приоритет: **65–100 — высокий**, **30–64 — средний**, **0–29 — низкий**. Готовность: от 20 баллов за проблему, действие, бюджет и роль — высокая; 10–19 — средняя; ниже — низкая. Приоритет и срочность могут различаться.

Рекомендуемое направление: при упоминании бота/Telegram — «Клиентские боты»; иначе при CRM/интеграции/обмене/синхронизации — «Интеграции»; при других распознанных признаках — «Автоматизация процессов»; иначе — «Первичная консультация». Для высокого приоритета рекомендуется персональный менеджер. Это подсказки, автоматического назначения сотрудника нет.

Бюджет «Нужна оценка» нейтрален. Длина текста, компания, ниша и её размер, поведение мыши, время заполнения и повторные посещения не повышают и не понижают оценку.

## Хранение и порядок

Оценка и версия правил сохраняются при создании заявки. Смена бюджета услуги не пересчитывает историю. Существующие заявки получают оценку при переходе с предыдущей версии приложения. Автоматический пересчёт при каждом просмотре отсутствует.

Администратор может задать ручной приоритет с обязательным комментарием. Автоматическая оценка остаётся видимой. Очистка ручного приоритета возвращает автоматический. Фильтры и сортировка используют эффективный приоритет.

Порядок: высокий → средний → низкий; внутри уровня новые необработанные → в работе → завершённые/отменённые; внутри группы более старые заявки идут первыми. Есть отдельная сортировка по дате.

## Синтетические примеры

Команда `python -m customer_orders.manage demo` внутри backend создаёт 10 вымышленных заявок: 4 высокого, 3 среднего и 3 низкого приоритета. Нужна хотя бы одна активная услуга. Контакты имеют домен example.com. Повторный запуск не дублирует существующие примеры; автоматически при деплое они не создаются. Набор и ожидаемые оценки находятся в `backend/src/customer_orders/demo.py` и проверяются тестами.

Использовать только там, где допустимы демонстрационные данные. Их можно найти по компании «Синтетический пример» и комментарию «Демонстрационные данные v1».
