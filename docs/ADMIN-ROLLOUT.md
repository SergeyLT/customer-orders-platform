# Переход с версии 0.2 на административную панель

1. До push выключите DEPLOY_ENABLED; ADMIN_DEPLOY_READY оставьте отсутствующим/false. Завершите ранее начатые workflow. Auto Deploy Coolify остаётся выключенным.
2. Сделайте резервную копию действующей PostgreSQL и сохраните согласованные предыдущие digest web/backend.
3. После успешных checks/publish нового коммита возьмите два новых digest одного релиза.
4. В существующем ресурсе приложения Coolify добавьте runtime JWT_SECRET (новый случайный секрет от 32 символов) и PUBLIC_ORIGIN (реальный адрес сайта HTTPS без порта :8080 и без пути). Пример генерации: `python -c "import secrets; print(secrets.token_urlsafe(48))"`. Секрет сохраняется между релизами; его смена делает все существующие JWT недействительными.
5. Удалите старые ADMIN_USERNAME/ADMIN_PASSWORD из ресурса после перехода: приложение их больше не читает. Это не удаляет пользователя PostgreSQL. APP_DB_PASSWORD и существующие POSTGRES_*/PGADMIN_* сохраняются.
6. Reload Compose File в том же ресурсе, оба новых digest в WEB_IMAGE/BACKEND_IMAGE, только web имеет домен. COOKIE_SECURE=true задан в production Compose и должен сохраняться. Выполните ручной Deploy.
7. Backend применит аддитивную миграцию 0002: добавит аккаунты/сеансы/аналитику и поля оценки. Заявки, услуги и старые behavior_metrics сохраняются; существующие заявки получают оценку v1. Проверьте health обоих компонентов.
8. На VPS найдите актуальный backend-контейнер этого ресурса. Выполните `docker exec -it <backend-container> python -m customer_orders.manage invite`, передайте код владельцу. Он открывает /admin → «Есть приглашение» → создаёт аккаунт. Код не записывать в общие логи. Процесс описан в [ADMIN.md](ADMIN.md).
9. Проверьте вход и выход, управление услугами, сохранение заявки, отображение приоритета и работу аналитики после согласия посетителя. После успешного запуска установите ADMIN_DEPLOY_READY=true и DEPLOY_ENABLED=true, запустите workflow вручную и подтвердите checks → publish → deploy.

При откате верните оба предыдущих digest. Дополнительные поля/таблицы обратно автоматически не удаляются. Старый backend требует прежний ADMIN_PASSWORD, поэтому при откате восстановите эти настройки из своего менеджера секретов. Не запускайте downgrade рабочей базы и не удаляйте тома для исправления ошибок. Не копируйте production-данные в общие тестовые окружения.
