# Администраторы и передача приложения

## Вход

Откройте `/admin`. Пароли хранятся в виде Argon2id-хешей. JWT подписывается HS256 отдельным JWT_SECRET и передаётся в HttpOnly cookie с Secure и SameSite=Strict. Срок сеанса — 8 часов, продления без входа нет. JWT не хранится в localStorage. В БД хранится отзываемый сеанс, поэтому выход, деактивация и смена пароля прекращают доступ до истечения JWT.

Изменяющие запросы проверяют X-CSRF-Token из GET /api/auth/me. Вход и первичная настройка принимают JSON и X-Requested-With: CustomerOrders; Origin при наличии должен совпадать с PUBLIC_ORIGIN. CORS не включён. Cookie имеет Path=/api, Domain не задан. Административная HTML-оболочка публична и не содержит данных, все её запросы защищены.

## Передача первому владельцу

После деплоя и миграций выполните на сервере:

```sh
docker exec -it <backend-container> python -m customer_orders.manage invite
```

Команда разрешена только пока в БД нет ни одного администратора. Она выдаёт случайный код на 24 часа; повторный выпуск аннулирует старый. В БД хранится только хеш кода. Не сохраняйте вывод в общие логи. Передайте владельцу адрес `/admin` и код по защищённому каналу.

Владелец нажимает «Есть приглашение», вводит код, затем задаёт собственные логин и пароль. Логин — 3–80 латинских букв, цифр, точек, дефисов или подчёркиваний; регистр не различается. Пароль — 16–128 символов. После создания аккаунта регистрация закрывается на сервере, код погашается и форма создания скрывается. Параллельные запросы защищены общей транзакционной блокировкой. Обычная кнопка «Есть приглашение» сама по себе не открывает регистрацию и остаётся способом ввести новый код после истечения старого.

Настройку не надо выполнять повторно при пересоздании контейнеров. Тома и схема orders сохраняют аккаунты.

## Дополнительные аккаунты

Раздел «Администраторы» доступен только после входа. Все аккаунты имеют одинаковые права. Можно создать нового администратора, активировать/деактивировать существующего и сбросить его пароль. Новый пароль передаётся адресату отдельно. Деактивация и сброс отзывают все сеансы пользователя. В «Мой пароль» нужно подтвердить текущий пароль, после изменения требуется повторный вход. Последнего активного администратора отключить нельзя; проверка защищена от параллельных операций.

## Восстановление

Если пароль утрачен, оператор с доступом к Docker выполняет:

```sh
docker exec -it <backend-container> python -m customer_orders.manage recover
```

Команда интерактивно запросит логин и новый пароль дважды, активирует существующий аккаунт и отзовёт его сеансы. Пароль не передаётся в аргументах и не печатается. Команда не создаёт нового скрытого аккаунта. Для первого пользователя используйте invite. Доступ к серверу/Docker эквивалентен административному доверию.

## Swagger

Сначала войдите на `/admin`, затем откройте `/api/admin/docs` в том же браузере. Swagger использует тот же сеанс; локальный swagger-auth.js добавляет CSRF для изменяющих запросов. Старый HTTP Basic и переменные ADMIN_USERNAME/ADMIN_PASSWORD больше не дают доступ. При завершении сеанса снова войдите через `/admin`.

Ограничения входа: 10 попыток на нормализованный логин за 15 минут, глобально 100 попыток за 15 минут; дополнительно Nginx ограничивает общий поток login до 10/мин с burst 10. Это общие ограничения, не IP-квоты. Приглашение: 30 проверок/регистраций за 15 минут. Для публичного сервиса с большим числом операторов следует адаптировать лимиты и добавить внешний контроль злоупотреблений.
